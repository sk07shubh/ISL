# ISL Interpreter — React Native app (on-phone)

Everything that recognises signs runs **on the phone**. There is no network call per frame, so latency is set by the camera and the phone, not by the connection.

## How it works
1. **Camera + hand tracking (native, Kotlin):** `modules/hand-tracker/`. CameraX shows the camera and MediaPipe HandLandmarker finds 21 points per hand on every frame, using the same `hand_landmarker.task` model as the website and `live_clean.py`.
2. **Features (TypeScript):** `src/lib/features.ts` is a port of `training/features.py`, producing the same 161 numbers.
3. **Classifiers (TypeScript):** `src/lib/model.ts` runs the three exported MLPs bundled in `assets/models/` (letters, digits, phrases).
4. **Rules:** `src/lib/recognizer.ts` applies smoothing (8 frames), per-model thresholds, stability (5 frames), and hold (600 ms), the same as the website.
5. **Parity check:** on start, the app recomputes a reference case generated by the Python code (`assets/golden.json`). Results shows "Matches the training code" only if it agrees.

The backend is used only to **save live-test results** and to show analytics. It is not needed to recognise signs.

## Important: camera screens are landscape
The model was trained on landscape webcam frames. The camera screens lock to landscape so the phone image has the same geometry. Results and Settings stay in portrait.

## Set up
1. Install Node.js LTS. In this folder: `npm install`
2. Set the backend address in `eas.json` (`EXPO_PUBLIC_API_URL`), for saving results.
3. Run `npm test` (logic and Python-parity tests) and `npm run typecheck`.

## Build on a phone (EAS)
Expo Go cannot load the native camera module, so use a development build:
```
npx eas-cli login
npx eas-cli init                                      # fills in extra.eas.projectId
npx eas-cli build -p android --profile development    # APK with the native module
```
Install the APK, then run `npx expo start --dev-client` and open it on the phone.
